# 原生移动输入接管（NativeHost 0.3）

原生 DLL 接管游戏自己的键盘移动动作读取。Lua 0.9.2 继续检测威胁和输出九方向评分，NativeHost 读取评分并写入共享内存，DLL 在本机键盘输入设备上返回选择的方向。没有 SendInput 调用，不覆盖网络设备、不写角色位置或速度。

## 启动与退出

先关闭旧的“以撒紧急躲弹”辅助窗口，启动游戏，再打开桌面的“以撒原生输入躲避”。保留现有传感器模组。第一次在单人空房间验证，再测试联机。

关闭原生辅助窗口、数据过期、游戏失焦或按住左 Alt 时恢复原始输入。DLL 留驻到游戏退出；它不会在仍有回调运行时卸载。游戏退出后 Hook 自然消失，磁盘上的游戏程序未修改。

仅支持 SHA256 为 `210cade2a1de98550cef52d012174108189d1a0d3926a22c3a1ec12fb3ae4831` 的安装版本，启动器校验文件，DLL 另校验 PE 时间戳、映像尺寸与原始虚表地址。游戏升级后拒绝安装 Hook。

## 当前验证范围

DLL 和 x86 .NET 启动器编译成功。在 Windows 上通过评分、无效分数、阻挡路线、未激活透传，以及 200000 次 thiscall/fastcall 调用的栈平衡和返回值检查。安装文件哈希一致。

用户已反馈原生程序能够产生一定移动，避伤效果仍有不足；Online 同步尚未验证。窗口的读取/替代输入计数是入口执行证据，不是角色移动回执。当前搭配传感器 0.9.2，预测算法见 [algorithm-0.9.md](research/algorithm-0.9.md)，本轮激光计算优化见 [performance-0.9.2.md](research/performance-0.9.2.md)。

## 构建

Linux 运行 `bash native/build-dll.sh`。Windows 将 NativeHost.cs、PacketClock.cs、build-host.ps1 放在同一目录并执行构建脚本；将 DLL 放在生成的 EXE 旁。PacketClock 沿用辅助程序 0.1.1 的时钟校准算法。

## 0.2 决策修正（传感器 0.8.5）

修复首帧惯性撞墙导致所有移动候选误判为堵死；仅当接管后整个轨迹都不发生位移时禁用方向。原生选择增加同伤害等级内的方向保持，容差为 64 个终点空间成本单位；安全的手动方向立即归还控制，旧方向变危险或堵塞时立即放弃。16ms 决策缓存不再因每条新评分到达而提前失效。

新增墙边逃脱、持续堵墙、相近路线保持、堵塞切换、安全优先和手动归还回归检查。以上为确定性场景验证，实际避伤改善待游戏验证。0.2 单独安装，旧 DLL 已驻留时需要重启游戏。

## 0.3 读取延迟与决策缓存

0.2 用 WinForms 定时器读日志，16ms 间隔在默认系统时钟精度下实际约 31ms 触发一次。0.3 改为独立线程以 1ms 间隔读取（`timeBeginPeriod(1)`），界面定时器只负责显示。`Isaac.GetTime()` 在当前安装版本上与 `QueryPerformanceCounter` 毫秒同源（2026-10-24 实测日志行可见时差 3～31ms，含读取开销），因此窗口直接显示每条评分从写出到被读取的延迟 p50/p95/最大值，并每 30 秒及退出时追加到 `%LOCALAPPDATA%\IsaacDodgeAssist\native-0.3-stats.log`。

DLL 原先用 `GetTickCount` 判断 16ms 内复用决策；该计时以约 16ms 跳变，可能把一次决策沿用到下一个 60Hz 玩家帧。0.3 只在同一设备、同一评分序号且性能计数器 4ms 内复用。共享内存布局与 IAD1 协议不变；0.2 DLL 已驻留时需要重启游戏，再打开 0.3。

Windows 编译与 ABI 测试（`tests/abi_and_ranking.cpp` 交叉编译后在 Windows 运行）通过。

0.9.2 保持 IAD1 九方向、阻挡位和 `1048576` 风险分层，继续兼容 NativeHost 0.2，不需要重新构建或更新 DLL。Lua 增加爆炸弹保守预警、弹体受伤诊断和短战斗性能统计；激光检查改用数值坐标。游戏内避伤、帧率与 Online 同步仍待验证。
